## Что это за проект

Сайт-портфолио веб-разработчика. Максим, псевдоним **manath**, Нижнекамск,
делает лендинги и многостраничники для местного бизнеса. Работает один, без
агентства. Боевой адрес — **https://manath.site**.

Сайт одновременно портфолио и рабочий инструмент привлечения: он должен
приводить заявки из поиска, а не просто показывать работы. Отсюда две вещи,
которые определяют почти все решения в коде:

1. **Сайт сам себе доказательство.** Он продаёт умение делать быстрые,
   честные, хорошо структурированные сайты — значит должен быть таким сам.
   Медленная страница или выдуманная цифра здесь стоят дороже, чем на обычном
   сайте: они опровергают тезис.
2. **Ничего выдуманного.** Ни цифр, ни клиентов, ни отзывов. Это не
   абстрактная этика, а позиционирование: на первом экране написано «ни одного
   шаблона с автозаменой города», и всё остальное обязано этому соответствовать.

## Правила, которые важнее остальных

**Ни одной выдуманной цифры.** Нигде. Свои цены и сроки называются как есть
(от 45 000 ₽, от 7 дней), чужие — как наблюдение и с оговоркой, что это
наблюдение. Статистики вида «68 % пользователей» не существует: нет источника —
нет цифры.

**Ни одного непроверяемого утверждения о чужом бизнесе.** Работа помечается
клиентской, только если заказ был. Из одиннадцати работ клиентская одна —
`massage-nk`. Остальные несут в подвале собственную оговорку
«Демонстрационный макет из портфолио — не действующий сайт компании», поэтому
снять флаг `isDemo` можно только вместе с этой строкой в самом макете, иначе
сайт опровергает сам себя в один клик.

**Восемь запретов из спеки** (часть 2, «Восемь запретов») — антислоп-список.
Коротко: ноль эмодзи, ноль абстрактных 3D-фигур и нейросетевых иллюстраций, не
больше двух свечений на экран, никаких ровных сеток из одинаковых карточек,
никаких заголовков «Мы» и «Почему выбирают», не больше трёх эффектных
компонентов на страницу, никакой анимации ради анимации, ни одной придуманной
цифры.

**Комментарий объясняет причину, а не действие.** В этом коде комментарии
отвечают на «почему так, а не иначе», и часто фиксируют, что уже пробовали и
почему это не подошло. Пишите так же — иначе следующий рефакторинг отменит
решение, у которого была причина.

## Стек и как это собирается

Next.js 15 (App Router, `output: 'export'`), React 19, Tailwind v4,
lucide-react, sonner. Эффектные компоненты из Magic UI и Aceternity не
подключены зависимостями, а переписаны под токены проекта в
`src/components/ui/`.

Вывод статический, потому что хостинг — обычный Apache. Отсюда:

- `trailingSlash: true` — без него `/kazan/` отдаст 404;
- `images.unoptimized` — в экспорте `next/image` не оптимизирует, картинки
  готовятся заранее в WebP скриптами;
- всё, что зависит от рантайма, вынесено наружу: форма шлёт в Cloudflare
  Worker или в PHP-приёмник.

**Выкладка автоматическая.** Пуш в `main` запускает
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) — сборка и
публикация на GitHub Pages с собственным доменом. Занимает около двух минут.
Переменных окружения в workflow нет намеренно: боевой адрес, счётчик Метрики
и приёмник заявок живут в `src/data/site.ts`, одно место вместо двух.

`NEXT_PUBLIC_BASE_PATH` существует для копии на `manath-iq.github.io/portfolio-v2/`,
где сайт живёт по подпути. Все ссылки на файлы и внутренние страницы проходят
через `asset()` из [`src/lib/asset.ts`](src/lib/asset.ts), включая `@font-face`.
На боевом домене префикс пустой.

### Ниши

Десять страниц вида `/sayt-dlya-stomatologii/` — по одной на нишу, у которой
есть готовая работа. Ядро каждой — блок «структура»: порядок экранов под нишу
и причина каждого.

**Города и ниши не перемножаются.** «Сайт для стоматологии в Казани» и ещё
двадцать девять таких же — это дорвеи, за них снимают весь сайт. Если такая
страница когда-нибудь понадобится, она должна быть одна, написанная руками,
про реальный проект в этом городе и этой нише.

## Дизайн-система

Полностью описана в спеке, часть 2. Токены живут в
[`src/styles/globals.css`](src/styles/globals.css), Tailwind читает их через
`@theme inline`.

Тёмная стеклянная страница. Фон `#0A0A0C`, акцент `#FF4D2E`, второй акцент
`#FFA23A`, светлая секция на `#F4F2ED`. Радиусы 12 / 20 / 28 / 40 / pill.
Движение — `280ms` и `cubic-bezier(.22,1,.36,1)`.

Шрифтов ровно три, каждый в своей роли: Onest — основной, JetBrains Mono —
микротекст и цифры, Playfair Display Italic — акцентное слово в заголовках.
Акцентное слово везде оформляется одинаково, через компонент `W`.

Зерно лежит одним слоем на всю страницу (`opacity: .035`,
`mix-blend-mode: overlay`) — локальное зерно внутри блоков добавлять не надо,
получаются помехи.

`--text-3` однажды уже поднимали с `#6c6a65` до `#85827c`: старый давал 3,66:1
на фоне, ниже порога AA. Этим цветом набраны цена, срок и гарантия — понижать
обратно нельзя.

## Формы и аналитика

**Форма заявки** отправляет в Telegram без перезагрузки. Приёмник зависит от
хостинга, фронтенд одинаковый:

- на статике — Cloudflare Worker, [`workers/lead.js`](workers/lead.js),
  инструкция в шапке файла. Токен бота лежит в секретах воркера;
- на хостинге с PHP — [`public/api/lead.php`](public/api/lead.php).

Адрес в `SITE.leadEndpoint`, переменная сборки `NEXT_PUBLIC_LEAD_ENDPOINT`
главнее. Если приёмника нет, поля формы **не выводятся вовсе** — вместо них
прямые контакты. Форма, которая молча ничего не отправляет, хуже её
отсутствия: человек пишет задачу, жмёт кнопку и теряет написанное.

**Метрика** — счётчик `111665281`. Девять целей расставлены по секциям,
вызовы идут через `goal()` из [`src/lib/metrika.ts`](src/lib/metrika.ts):
`lead_sent`, `form_start`, `cta_click`, `phone_click`, `tg_click`, `wa_click`,
`open_site`, `tg_post`, `hero_tab`. Актуальный список всегда можно достать
командой `grep -rhoE "goal\('[a-z_]+'\)" src/ | sort -u` — в `TODO.md` он
устаревал.

Вебвизор выключен намеренно: он пишет ввод в поля, а через форму идут
телефоны живых людей.

## Раздел статей

### Зачем он существует

Закрывает информационные запросы: «сколько стоит сайт», «лендинг или
многостраничник», «почему сайт не в поиске». Человек приходит по ним за
месяц-два до того, как готов платить, и приходит бесплатно.

Это единственный быстрый вход, пока у домена нет ссылочного: молодому домену
информационные запросы отдают охотнее коммерческих. По проверке 28.08.2026
Google индексирует новую статью здесь за один-два дня, тогда как по запросу
«создание сайтов Нижнекамск» сайта нет в топ-30 и не будет ещё месяцы.

Раздел называется «статьи», а не «разборы»: слово занято разборами работ.

### Из чего состоит статья

Текст хранится не строкой с HTML и не markdown, а массивом типизированных
блоков. У блока есть тип, поэтому таблица не может приехать без шапки, а
заголовок — оказаться внутри абзаца. Плюс контент остаётся данными, и по нему
честно считается время чтения: руками его не проставляют.

```ts
{ t: 'p'; text: string }                              // абзац
{ t: 'h'; text: string }                              // подзаголовок (h2)
{ t: 'list'; items: string[] }                        // список
{ t: 'note'; text: string }                           // врезка
{ t: 'table'; head: string[]; rows: string[][] }      // таблица
{ t: 'figure'; kind: 'first-screen' | VisualKind }    // схема по тексту
```

Поля статьи:

```ts
slug            // латиницей, из него собирается /stati/<slug>/
h1              // заголовок на странице
lead            // подзаголовок под h1, одно-два предложения
title           // <title>, заканчивается на « | manath»
description     // мета-описание, 140–170 знаков
date            // ISO, дата первой публикации
summary?        // 3–4 вывода для пересказа от ИИ
visual?         // мотив обложки, если он осмыслен
relatedNiches   // slug'и из niche-pages.ts
relatedCases    // slug'и из cases.ts
blocks          // тело
```

### Как писать текст

Голос тот же, что на всём сайте: обращение на «вы», короткие абзацы,
конкретика вместо усилителей. Приёмы, которые в разделе уже сложились:

- Начинать с того, что человек уже думает, и разворачивать это. Не с
  определений и не с «в современном мире».
- Говорить то, что невыгодно. «Есть бизнесы, которым сайт сейчас не нужен» в
  статье про сайты работает сильнее любого аргумента за.
- Разводить понятия, которые путают. «Сайта нет в поиске» и «заявок нет» —
  разные беды с разным лечением, и половина статьи может уйти на это.
- Давать проверку, которую можно сделать сегодня и без подрядчика.
- Заканчивать не выводом, а тем, что делать дальше.

Врезка `note` — не украшение ритма. В неё выносится то, что человек должен
унести, даже если читал по диагонали. Одна-три на статью.

### Пересказ от ИИ

Поле `summary` — три-четыре вывода. Пишутся вместе со статьёй, по тем же
правилам про цифры: ни одной, которой нет в тексте.

Блок свёрнут в кнопку «Пересказ от ИИ». По нажатию идёт пауза 700 мс с
пульсирующими точками, затем текст печатается порциями по 2–5 знаков с
акцентной кареткой. Причины, которые стоит сохранить при правках:

- **Свёрнут, а не открыт.** Готовые выводы над текстом снимают повод читать
  сам текст: человек забирает четыре строки и уходит. Кнопка оставляет выбор
  за ним.
- **Печатается, а не появляется.** Пауза и набор показывают, что ответ
  собирается сейчас. Мгновенно появившийся абзац читался бы как заранее
  написанная врезка от автора, то есть ровно как то, чем он не является.
- **Текста нет в разметке, пока кнопку не нажали.** Пересказ производен от
  статьи, и отдавать поисковику второй раз тот же смысл на той же странице
  незачем.
- При `prefers-reduced-motion: reduce` пауза и набор пропускаются: для этого
  человека они не эффект, а задержка ответа.

Счётчик знаков живёт в `ref`, а не только в состоянии. Планировать следующий
шаг внутри `setState` нельзя: `reactStrictMode` включён, обновление
вызывается дважды, цепочка таймеров раздваивается и текст набирается вдвое
быстрее заданного. Это уже ловили.

### Схемы

Поле `visual` и блок `figure` рисуют схему из `ArticleVisual.tsx`. Мотивы:
`funnel`, `timeline`, `checklist`, `tiers`, `entries`, `channels`. Плюс
отдельная `first-screen` из `FirstScreenDiagram.tsx`.

**Схемы собраны вёрсткой, а не картинками, и так должно остаться.** Ноль байт
в бюджет первого экрана, резкость на любом экране, акцент и фон из токенов.
Растровая обложка на каждую из тринадцати статей стоила бы сотни килобайт и
устаревала бы при первой правке заголовка. Нарисованная нейросетью иллюстрация
запрещена отдельно, пунктом 2 «Восьми запретов»: сайт сам пишет, что стоковое
фото узнаётся мгновенно и роняет доверие, а ИИ-картинка читается так же.

**Мотив показывает мысль, а не украшает статью.** Воронка — что заявки
теряются ступенями; шкала — что срок делится между двумя сторонами; чеклист —
что верхние пункты проверяют все, а нижние забывают. Нет такой мысли — нет и
визуала: из тринадцати статей схема есть у семи (пять обложек и две врезки), у
шести нет ничего, и это не недоделка.

Мотив ставится туда, где работает: `visual` — обложкой под шапкой,
`{ t: 'figure' }` — врезкой по тексту. У «сколько делается сайт» обложки нет
вовсе, потому что шкала объясняет третью колонку таблицы и стоит после неё.

Новый мотив рисуется руками, отдельным компонентом, тип добавляется в
`VisualKind` в `articles.ts`. Это осознанно дорого: цена не даёт наставить
картинок ради разнообразия.

При вёрстке схем полосы разной длины с подписями собираются **сеткой, а не
флексом**. Во флексе длинная подпись сжимает свою полосу сильнее соседних, и
воронка перестаёт сужаться по порядку — то есть врёт.

### Перелинковка

`relatedNiches` и `relatedCases` — по одному-два слага. Подбирать так, чтобы
разные статьи вели в разные углы сайта, а не все в одни и те же две страницы.
Слаги обязаны существовать, иначе блок «По теме рядом» молча недосчитается
карточки.

## Команды и порядок работы

```bash
npm run dev      # разработка
npm run build    # сборка в out/, postbuild печатает вес первого экрана
npx tsc --noEmit # типы
```

Отдельно, руками, по необходимости:

```bash
node scripts/og.mjs        # OG-картинки: главная, ниши, статьи
node scripts/capture.mjs   # скриншоты и записи скролла работ
node scripts/adaptive.mjs  # один сайт в трёх ширинах
node scripts/fonts.mjs     # woff2 из Google Fonts локально
node scripts/icons.mjs     # apple-touch-icon из favicon.svg
node scripts/cursor.mjs    # курсоры-значки
```

Скрипты со скриншотами поднимают headless Chrome по пути
`/Applications/Google Chrome.app` — на другой машине путь придётся поправить.

### Порядок добавления статьи

1. Дописать объект в `ARTICLES`. Новые — в конец: витрина и выпадающий список
   в шапке берут свежие с конца.
2. `npx tsc --noEmit`.
3. `npm run build` — `postbuild` печатает вес первого экрана, он не должен
   вылезти за 900 КБ (сейчас 630).
4. **`node scripts/og.mjs`** — без этого `public/og/stati-<slug>.jpg` не
   появится, а страница на него ссылается. Уже забывали: четыре статьи неделю
   отдавали 404 на своё превью.
5. Посмотреть глазами на дев-сервере.
6. Закоммитить и запушить в `main` — выкладка идёт сама, около двух минут.
7. Отправить новые адреса на переобход в Яндекс.Вебмастере (Индексирование →
   Переобход страниц, лимит 150 в сутки). Витрину `/stati/` вместе со
   статьями: на ней меняется список. Google находит сам за день-два, ему
   заявка не нужна.

### Проверка перед сдачей

Чеклист части 8 спеки: страница читается с выключенным JS, карусель не

## Грабли, на которые уже наступали

- **Дев-сервер поднимать только через `preview_start`, не через Bash.**
- **Не запускать `npm run build`, пока дев-сервер живёт**: сборка затирает
  `.next`, и сервер начинает отдавать 500 с `MODULE_NOT_FOUND`.
- **Не убивать всё подряд из `lsof -ti:3000`** — команда возвращает и
  клиентов тоже, под раздачу попадут чужие процессы. Фильтровать по `LISTEN`.
- **`og.mjs` после каждой новой статьи или ниши.** См. выше.
- **Таймер внутри `setState`** раздваивается в StrictMode.
- Для скриншотов headless-браузером эмулируйте
  `prefers-reduced-motion: reduce` — иначе `Reveal` держит содержимое
  невидимым и кадр выходит пустым.
