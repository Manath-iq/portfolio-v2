## Общие правила, которые важнее остальных

**Ни одной выдуманной цифры.** Нигде на сайте. Свои цены и сроки называются
как есть (от 45 000 ₽, от 7 дней), чужие — как наблюдение и с оговоркой, что
это наблюдение. Статистики вида «68 % пользователей» не бывает: если источник
не назван и не проверяется, цифры нет.

**Ни одного утверждения о чужом бизнесе, которое нельзя проверить.** Работа
помечается клиентской только если заказ действительно был. Девять макетов в
портфолио несут в подвале собственную оговорку «Демонстрационный макет из
портфолио — не действующий сайт компании», и снять флаг `isDemo` можно только
вместе с этой строкой в самом макете.

**Ноль эмодзи.** Иконки — только Lucide, обводка 1.5.

**Комментарий объясняет причину, а не действие.** В коде этого проекта
комментарии отвечают на «почему так, а не иначе», и часто описывают, что уже
пробовали и почему это не подошло. Пишите так же.

## Раздел статей

### Зачем он существует

Раздел закрывает информационные запросы: «сколько стоит сайт», «лендинг или
многостраничник», «почему сайт не в поиске». Человек приходит по ним за
месяц-два до того, как готов платить, и приходит бесплатно.

Это единственный быстрый вход, пока у домена нет ссылочного: молодому домену
информационные запросы отдают охотнее коммерческих. По проверке 28.08.2026
Google индексирует новую статью здесь за один-два дня, тогда как по запросу
«создание сайтов Нижнекамск» сайта нет в топ-30 и не будет ещё месяцы.

Раздел называется «статьи», а не «разборы»: слово уже занято разборами работ
на `/raboty/`.

### Из чего состоит статья

Текст хранится не строкой с HTML и не markdown, а массивом типизированных
блоков. У блока есть тип, поэтому таблица не может приехать без шапки, а
заголовок не может оказаться внутри абзаца. Плюс контент остаётся данными, и
по нему честно считается время чтения — руками его не проставляют.

```ts
{ t: 'p'; text: string }                              // абзац
{ t: 'h'; text: string }                              // подзаголовок (h2)
{ t: 'list'; items: string[] }                        // список
{ t: 'note'; text: string }                           // врезка
{ t: 'table'; head: string[]; rows: string[][] }      // таблица
{ t: 'figure'; kind: 'first-screen' | VisualKind }    // схема по тексту
```

Поля самой статьи:

```ts
slug            // латиницей, из него собирается адрес /stati/<slug>/
h1              // заголовок на странице
lead            // подзаголовок под h1, одно-два предложения
title           // <title>, заканчивается на « | manath»
description     // мета-описание, 140–170 знаков
date            // ISO, дата первой публикации
summary?        // 3–4 вывода для пересказа от ИИ
visual?         // мотив обложки, если он осмыслен
relatedNiches   // slug'и из niche-pages.ts
relatedCases    // slug'и из cases.ts
blocks          // тело
```

### Как писать текст

Голос ровно тот же, что на всём сайте: обращение на «вы», короткие абзацы,
конкретика вместо усилителей. Работающие приёмы, которые уже сложились в
разделе:

- Начинать с того, что человек уже думает, и разворачивать это. Не с
  определений и не с «в современном мире».
- Говорить то, что невыгодно. «Есть бизнесы, которым сайт сейчас не нужен» в
  статье про сайты работает сильнее любого аргумента за.
- Разводить понятия, которые путают. «Сайта нет в поиске» и «заявок нет» —
  две разные беды с разным лечением, и половина статьи может уйти на то,
  чтобы это различить.
- Давать проверку, которую можно сделать сегодня и без подрядчика.
- Заканчивать не выводом, а тем, что делать дальше.

Врезка `note` — не украшение ритма. В неё выносится то, что человек должен
унести, даже если читал по диагонали. Одна-три на статью.

### Пересказ от ИИ

Поле `summary` — три-четыре вывода. Пишутся вместе со статьёй, по тем же
правилам про цифры: ни одной, которой нет в тексте.

Как это работает на странице. Блок свёрнут в кнопку «Пересказ от ИИ». По
нажатию идёт пауза 700 мс с пульсирующими точками, затем текст печатается
порциями по 2–5 знаков с акцентной кареткой.

Почему именно так, и это стоит сохранить при правках:

- **Свёрнут, а не открыт.** Готовые выводы над текстом снимают повод читать
  сам текст: человек забирает четыре строки и уходит. Кнопка оставляет выбор
  за ним.
- **Печатается, а не появляется.** Пауза и набор показывают, что ответ
  собирается сейчас. Мгновенно появившийся абзац читался бы как заранее
  написанная врезка от автора, то есть ровно как то, чем он не является.
- **Текста нет в разметке, пока кнопку не нажали.** Пересказ производен от
  статьи, и отдавать поисковику второй раз тот же смысл на той же странице
  незачем.
- При `prefers-reduced-motion: reduce` и пауза, и набор пропускаются: для
  этого человека они не эффект, а задержка ответа.

Счётчик знаков живёт в `ref`, а не только в состоянии. Планировать следующий
шаг внутри `setState` нельзя: `reactStrictMode` включён, обновление
вызывается дважды, цепочка таймеров раздваивается и текст набирается вдвое
быстрее заданного. Это уже ловили один раз.

### Схемы

Поле `visual` и блок `figure` рисуют схему из
[`ArticleVisual.tsx`](src/components/article/ArticleVisual.tsx). Мотивы:
`funnel`, `timeline`, `checklist`, `tiers`, `entries`, `channels`. Плюс
отдельная `first-screen` из `FirstScreenDiagram.tsx`.

**Схемы собраны вёрсткой, а не картинками, и так должно остаться.** Причины:
ноль байт в бюджет первого экрана (сейчас 630 из 900 КБ), резкость на любом
экране, акцент и фон берутся из токенов. Растровая обложка на каждую из
тринадцати статей стоила бы сотни килобайт и устаревала бы при первой правке
заголовка. Нарисованная нейросетью картинка сюда не подходит отдельно: сайт
сам пишет, что стоковое фото узнаётся мгновенно и роняет доверие, а
абстрактная ИИ-иллюстрация читается так же.

**Главное правило: мотив показывает мысль, а не украшает статью.** Воронка
показывает, что заявки теряются ступенями; шкала — что срок делится между
двумя сторонами; чеклист — что верхние пункты проверяют все, а нижние
забывают. Если для статьи такой мысли нет, у неё нет и визуала — и это
нормально: из тринадцати статей схема есть у семи (пять обложек и две врезки),
у шести нет ничего. Пустая картинка ради ритма хуже, чем её отсутствие.

Мотив ставится туда, где работает: `visual` — обложкой под шапкой,
`{ t: 'figure' }` — врезкой по тексту. У «сколько делается сайт» обложки нет
вовсе, потому что шкала объясняет третью колонку таблицы и стоит после неё.

Новый мотив рисуется руками, отдельным компонентом, и его тип добавляется в
`VisualKind` в `articles.ts`. Это осознанно дорого: цена не даёт наставить
картинок ради разнообразия.

При вёрстке схем: полосы разной длины с подписями собираются сеткой, а не
флексом. Во флексе длинная подпись сжимает свою полосу сильнее соседних, и
воронка перестаёт сужаться по порядку — то есть врёт.

### Перелинковка

`relatedNiches` и `relatedCases` — по одному-два slug'а. Подбирать так, чтобы
разные статьи вели в разные углы сайта, а не все в одни и те же две страницы.
Slug'и обязаны существовать в `niche-pages.ts` и `cases.ts`, иначе блок «По
теме рядом» молча недосчитается карточки.

## Порядок добавления статьи

1. Дописать объект в `ARTICLES` в [`src/data/articles.ts`](src/data/articles.ts).
   Новые в конец: витрина и выпадающий список в шапке берут свежие с конца.
2. `npx tsc --noEmit` — типы.
3. `npm run build` — сборка. `postbuild` печатает вес первого экрана, он не
   должен вылезти за 900 КБ.
4. **`node scripts/og.mjs`** — сгенерировать превью. Без этого шага
   `public/og/stati-<slug>.jpg` не появится, а страница на него ссылается, и
   в Telegram с WhatsApp вместо превью будет пустота. Этот шаг уже забывали:
   четыре статьи неделю отдавали 404 на свою картинку.
   Скрипт поднимает headless Chrome по пути
   `/Applications/Google Chrome.app`, на другой машине путь надо поправить.
5. Проверить страницу глазами на дев-сервере. **Дев-сервер поднимать только
   через `preview_start`, не через Bash.** И не запускать `npm run build`,
   пока дев-сервер живёт: сборка затирает `.next`, и сервер начинает отдавать
   500 с `MODULE_NOT_FOUND`.
6. Закоммитить и запушить в `main` — выкладка на manath.site идёт сама через
   [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml), около двух
   минут.
7. Отправить новые адреса на переобход в Яндекс.Вебмастере: раздел
   «Индексирование → Переобход страниц», лимит 150 адресов в сутки. Google
   находит сам за день-два, ему заявка не нужна. Витрину `/stati/` отправлять
   вместе со статьями — на ней меняется список.

## Полезное про окружение

- Вывод статический (`output: 'export'`), хостинг — обычный Apache. Отсюда
  `trailingSlash: true` и `images.unoptimized`.
- Картинки готовятся заранее в WebP, `next/image` в экспорте не оптимизирует.
- Движение отключается через `prefers-reduced-motion`; `Reveal` при этом
  просто не прячет содержимое. Это же свойство удобно для скриншотов
  headless-браузером: без него содержимое остаётся невидимым.
- Освобождая порт, не убивайте всё подряд из `lsof -ti:3000` — команда
  возвращает и клиентов тоже. Фильтруйте по `LISTEN`.
